# Asset pipeline

Source content → `AssetPacker` → archives in `IronRing_Data/` → virtual file system at runtime. Decision record: [ADR-0004](adr/0004-asset-archives.md).

## Where things go

| You add | Put it in | Packed into | Virtual path |
| --- | --- | --- | --- |
| UI art, fonts, effects, HUD data | `Assets/Resources/...` | `resources.assets` | `Resources/...` |
| Sound effects, music (WAV/OGG/FLAC) | `Assets/Resources/Audio/...` | `resources.resource` | `Resources/Audio/...` |
| Fighter definition, atlas, portrait | `Assets/Fighters/<Name>/` | `sharedassets0.assets` | `Fighters/<Name>/...` |
| Stage art | `Assets/Stages/<Name>/` | `sharedassets0.assets` | `Stages/<Name>/...` |
| Content tables (roster, stages, palette) | `Assets/Data/` | `sharedassets0.assets` | `Data/...` |
| Game-wide settings, input bindings | `ProjectSettings/` | `globalgamemanagers` | `ProjectSettings/...` |

A new top-level folder under `Assets/` needs a rule in `ProjectSettings/AssetPipeline.json`; otherwise AssetPacker prints `not packed: ...` for each file in it.

## Rules file

```json
{
  "output": "resources.resource",   // file name in IronRing_Data
  "root": "Assets",                 // virtual paths are relative to this
  "include": ["Resources"],         // folders under root, scanned recursively
  "extensions": [".wav", ".ogg"],   // optional allow-list
  "excludeExtensions": []           // optional deny-list
}
```

CMake reads only the `output` names (to declare build outputs); AssetPacker reads everything. A virtual path claimed by two archives fails the build. Dotfiles, `Thumbs.db`, `desktop.ini` and `*.lnk` are ignored.

## Building and inspecting

The `PlayerData` target runs automatically with the player build whenever anything under `Assets/` or `ProjectSettings/` changes. By hand:

```sh
Build/debug/Tools/Debug/AssetPacker --project . --pipeline ProjectSettings/AssetPipeline.json --output /tmp/IronRing_Data
Build/debug/Tools/Debug/AssetPacker --list Build/debug/Player/Debug/IronRing_Data/sharedassets0.assets
```

Archives are ordinary ZIP files (`unzip -l` works). Output is byte-identical for identical inputs, on any machine and time zone.

## Iterating without repacking

```sh
IronRing.x86_64 -screen-fullscreen 0 -assets-folder ../../../../Assets
```

The loose folder is mounted last, so its files override the packed ones. `ProjectSettings/` is not covered by this override yet — repack after changing settings.

## Formats

- **Images:** PNG (RGBA), decoded with SDL's built-in loader. Stored, not deflated.
- **Audio:** WAV for short effects (decoded to PCM at load), OGG for music (streamed, looping from `music.json`'s loop point). Stored. Generated by `Tools/Audio/` ([docs/audio.md](audio.md)).
- **Data:** JSON, deflated.
- **Sprite atlases:** JSON next to the PNG with `image` and `frames[]` (`name`, `source_rect` `[x,y,w,h]`, `pivot_pixels`, optional `partner`). Full art contract: [docs/art/asset-spec.md](art/asset-spec.md).
- **Fighters:** `<id>.fighter.json`, listed in `ProjectSettings/GameSettings.json → fighters` ([ADR-0010](adr/0010-fighter-content-format.md)). The character select shows every fighter in `GameSettings.json → roster` (`Data/roster.json`), in its order; those without a definition are locked slots.
- **Arcade ladder:** `GameSettings.json → arcade` (`Data/arcade.json`): bouts of stage, opponent (`rival`, `mirror` or a fighter id), CPU level and `final`; AssetPacker checks stages and opponents.
- **Front end:** `GameSettings.json → ui` names the title logo, the menu backdrop and the menu theme (an id in `music.json`).

## Validation

Before writing any archive, AssetPacker validates the content it is about to pack (`Source/Content/Validation.cpp`): `GameSettings.json` references, every fighter definition (schema, move inputs, required animations, frames present in the atlas, animation lengths equal to move frame data, throw holds equal to `throwDuration`, knockdown length), atlases and their PNGs, stage sizes (warning if not 640×360), effects, fonts, sounds, the roster file and the front-end art and theme. Errors fail the build with the file and the problem; warnings are printed. The same checks run in `ContentTests` against the shipped project.

## Art sources

The art under `Assets/` is generated by `Tools/Art/generate.py` or imported with `Tools/Art/import_art.py` ([Tools/Art/README.md](../Tools/Art/README.md)). Both are run by hand and their output is committed; the build only packs it.
